# Appointment Booking System

A small appointment booking API — one calendar, no accounts, no double-booking.
Built following the Spec-Driven Development pipeline (constitution → spec →
clarify → plan → tasks → implement → verify).

## How to run

```
pip install -r requirements.txt
uvicorn app.main:app --reload
```

Run tests:
```
pytest
```

## How this was built

| Step | File | How it was made |
|---|---|---|
| Constitution | `constitution.md` | Written manually — project-wide rules (stack, error format, testing rules) |
| Spec | `spec.md` | Written manually — functional requirements (FR) and acceptance criteria (AC) |
| Clarify | (folded into spec.md) | Ambiguities flagged, discussed, and resolved before planning started |
| Plan | `plan.md` | Generated by opencode (desktop app), using prompt engineering guided by the Spec-Driven Development session material |
| Tasks | `tasks.md` | Generated by opencode (desktop app), same method as plan.md |
| Implement | `app/`, `tests/` | Built by opencode, with prompts drafted with help from Claude AI |
| Verify | — | Review pass run through opencode to check test coverage and catch weak assertions before submission |

## What it does

- Book an appointment (date, time, name, email, attendees)
- Rejects overlapping bookings on the same date
- One appointment per email per day
- Bookings must be 2+ hours ahead
- Open Sunday–Thursday, 08:00–18:00 only
- No accounts, no logins — just bookings

Full requirements are in `spec.md`. Full technical decisions are in `plan.md`.
